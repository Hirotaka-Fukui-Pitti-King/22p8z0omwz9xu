# Mandatory Julia contribution checks

Applies to every change under `FMR-2020/`, including code generated by AI agents in new conversations.

1. Do not use Julia reserved words (`macro`, `module`, `struct`, `function`, `quote`, `end`, `mutable`, `baremodule`, etc.) as identifiers. Prefer descriptive nouns, e.g. `realized_macro`.
2. Never infer success from a clean diff, a code review, or Julia code appearance. Check the actual exit code and output. If a Julia runtime is unavailable, clearly label execution as **not verified**. Do not claim the GitHub workflow has passed without inspecting its actual status.
3. Verify Julia stdlib/package UUIDs from the active registry or official source instead of inventing them.
4. After any correction, repeat checks 2–3; do not stop at changing the single reported line.
5. Preserve paper equations, information sets, and the original calibration. Code changes and numeric claims require independent validation.

If you cannot execute Julia in the current environment, prefer making the change with an explicit request for local/CI verification rather than presenting it as proven correct.
