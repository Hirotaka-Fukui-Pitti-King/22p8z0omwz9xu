# Mandatory Julia contribution checks

Applies to every change under `Nirei-2015/`, including code generated by AI agents in new conversations.

1. Do not use Julia reserved words (`macro`, `module`, `struct`, `function`, `quote`, `end`, `mutable`, `baremodule`, etc.) as identifiers. Prefer descriptive nouns, e.g. `realized_macro`.
2. Before claiming Julia code is runnable, execute the syntax gate: `julia --project=. scripts/check_julia_syntax.jl` from `Nirei-2015/`.
3. Then execute `julia --project=. -e 'using Pkg; Pkg.instantiate(); using Nirei2015'`, followed by the specific touched script and a minimal run of the actual changed path.
4. Never infer success from a clean diff, a code review, or Julia code appearance. Check the actual exit code and output. If a Julia runtime is unavailable, clearly label execution as **not verified**. Do not claim the GitHub workflow has passed without inspecting its actual status.
5. Verify Julia stdlib/package UUIDs from the active registry or official source instead of inventing them.
6. After any correction, repeat checks 2–3; do not stop at changing the single reported line.
7. Keep GitHub Actions `.github/workflows/julia-nirei.yml` passing. Do not bypass, disable, or weaken it merely to merge a change.
8. Preserve paper equations, information sets, and the original calibration. Code changes and numeric claims require independent validation.

If you cannot execute Julia in the current environment, prefer making the change with an explicit request for local/CI verification rather than presenting it as proven correct.
